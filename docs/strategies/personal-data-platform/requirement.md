# 個人用データ基盤のアーキテクチャ方針決定

## 作りたい戦略

自分用の個人的なデータ基盤を構築したい。
そのためのアーキテクチャの方針を決定する。

## 背景

私はデータエンジニアであり、仕事では所属企業のデータ基盤を開発・運用している。
一方、自分の孤児的なデータはあまり集約・管理できておらず、このための自分だけのデータ基盤を構築したいと考えている。

通常データ基盤は次のような要素で構築される。

- query engine
- data pipeline (workflow)
- data ingestion
- storage
- table format
- BI
- etc.

それぞれの技術スタックを決定したい。

## 要件

技術スタックの選定にあたっては以下を考慮したい。

- クラウド等への課金については無料または低コスト
- データ量はあまり大きくない
- MCP 等で Claude Code (やできれば Claude Desktip にも) とつないで使用したい
  - ローカルで接続できれば OK
- 個人の情報なのでセキュリティには気をつけたい
- 運用の手間を小さくしたい

## データソース

データソースとしては次のようなものを考えている。

- Oura Ring の API から取得する健康・運動データ
- MoneyForward から download した収入・支出や資産のデータ
- Suunto のスマホアプリから export した FIT または JSON 形式のスキューバダイビングのデータ
  - Suunto D5 というダイビングコンピュータの記録
- 健康診断の結果 (手動入力)
- Todoist の API から取得する日々のタスクのデータ

データソースは今後増える可能性がある。
